Para quem vai manter o que foi entregue: o que foi feito e como, os requisitos cobertos, os arquivos e commits, as decisões e onde se aprofundar.

Visão geral Arquitetura O que foi feito Requisitos Arquivos Diffs Commits Decisões Aprendizados Atenção Referências

Visão geral

O regression de apps/cli/src/commands/task.rs compara baseline e saída atual sem as linhas que contêm trechos de regression_ignore (config/tasks.yml, lista simples, sem regex); o NN.diff segue completo. O arquivo accepted ganhou um 6º campo com o código de saída aceito; AcceptedRegression::covers aceita enquanto o código atual for o aceito, e linhas antigas de 5 campos valem pelo hash da saída inteira ou da saída sem as linhas ignoradas.

Arquitetura e componentes

  • apps/cli/src/commands/task.rs: regression_ignore, without_ignored, latest_acceptances, AcceptedRegression::covers e exit_code, accepted_regressions (splitn(6)), regression_acceptances e recorded_exit_code.
  • packages/harness/config/tasks.yml: chave regression_ignore.
  • packages/harness/skills/default/finish-task/SKILL.md: passos 2 e 4.

O que foi feito

  • TASK-01: 7 testes de integração (linhas ignoradas, projeto sem a chave, diff completo, aceite pelo código, código diferente, aceite antigo, guia do persist com aceite antigo); comparação filtrada; código de saída no accepted; finish-task atualizada; chave acrescentada aos projetos pelo vostok update.
  • Três testes da SPEC-007 foram ajustados ao comportamento novo; output_changed_after_the_acceptance_blocks_again foi removido, porque exigia o oposto do RF-05.
