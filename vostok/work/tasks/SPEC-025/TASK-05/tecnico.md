## O que foi feito

`documents.yml` ganhou os tokens de 2026-10 com os nomes da organização, `code_bg`, `calm_*`, `brand_*` e sombras; a fonte do texto passou a ser `font.text`, porque o `vostok update` só acrescenta chaves e manteria o `font.body` antigo com a fonte do sistema. `css_tokens` gera o claro em `:root`, o escuro em `prefers-color-scheme` e em `data-theme="dark"`, os gradientes e os `@font-face` das fontes de `templates/finalize/fonts/` (subconjunto woff2 gerado com `pyftsubset` via `uvx`: Inter 99,5 KB e Outfit 33,4 KB), com a função `base64` que já existia. `markdown_html_at` converte `#` a `###` em títulos a partir de um nível (`SECTION_HEADING` = 1; `TASK_HEADING` = 3 no técnico das tarefas) e cercas de código em `<pre><code>`. `numbers_html` monta a coluna de números da faixa a partir de `## Em números`. Os templates foram gerados no modelo C com o índice do B, mantendo o CSS dos fragmentos que o `finalize.rs` produz (entregas, diffs, linha do tempo, peças), só com os tokens novos.

Desvios do plano: os goldens da finalização reconstroem um harness antigo, e o HTML da SPEC-008 entra em commits gravados nos objetos git do grupo de commit; mudar esse HTML exigiria reescrever o histórico das fixtures. Por isso o `documents.yml` sem `bg` gera o CSS antigo (`legacy_css_tokens`), a fonte ausente é ignorada, e a marcação do índice e das seções de evidências continua a do `finalize.rs`, numerada por contador CSS no template. Nenhuma fixture mudou e `golden.rs` não foi alterado (a variável de regravação citada no plano não existe). Os prints usam a SPEC-023 arquivada numa cópia temporária (ajuste 4).
